# Paradiddle song / kit / recording (`.rlrr`)
Kind: chart

Doc status: complete · ROX: no · Category: others · Encoding: json

## Overview
`.rlrr` is Paradiddle's JSON file format for three things: custom songs (one file per difficulty), drum kit layouts (saved in `Paradiddle/Saved/DrumLayouts/`) and in-app recordings. The schema is published by the author in the open-source `ParadiddleUtilities` repository (`docs/rlrrschema.json`, JSON Schema draft-07, `$id` `rlrrschema_v0.7.json`). The Song Creator converts MIDI drum tracks to `.rlrr` using a YAML mapping from MIDI notes to drum classes. Do not confuse with the esoteric language "Paradiddle" (also `.rlrr`).

## Container & encoding
- Plain JSON (UTF-8). Written by the Song Creator with `json.dump(indent=4)`.
- Song layout: a folder `<SongName>/` containing `<SongName>_<Difficulty>.rlrr` where difficulty is `Easy`, `Medium`, `Hard` or `Expert`, the audio files (ogg recommended; up to 5 song tracks and 4 drum tracks), and a cover image (guide). Copy to `Paradiddle/Saved/Songs/` (PC) or `Paradiddle/Songs` on Quest.
- File names inside the JSON are bare file names relative to the song folder (the converter keeps only the last path component).
- The schema distinguishes nothing between song, kit and recording: they differ by which optional properties are present (kits have only `instruments`).

## Structure / metadata
Top-level (schema `required`: `version`, `instruments`):

| Property | Type | Meaning |
|---|---|---|
| `version` | number | schema version (the converter writes `0.7`; older layout files are version 0 and 0.5) |
| `authoringTool` | string | e.g. `ParadiddleUtilities MidiConverter` |
| `instruments[]` | Instrument | drum kit layout used by the song |
| `events[]` | DrumEvent or BPMEvent | timeline |
| `bpmEvents[]` | BPMEvent | the converter writes tempo events in this array (`out_dict["bpmEvents"]`) while the schema lists BPM events inside `events` [source discrepancy] |
| `audioFileData` | object | audio file names |
| `recordingMetadata` | object | title, artist and so on |

`Instrument`: `name` (unique instance name, e.g. `BP_Kick_C_1`), `class` (blueprint class, e.g. `BP_Kick_C`), `location` [x,y,z] world space, `rotation` [pitch,yaw,roll] degrees, `scale` [x,y,z]. Classes in the default kit: `BP_HiHat_C`, `BP_Kick_C`, `BP_Crash15_C`, `BP_Crash17_C`, `BP_FloorTom_C`, `BP_Ride17_C`, `BP_Ride20_C`, `BP_Snare_C`, `BP_Tom1_C`, `BP_Tom2_C`. The MIDI mapping file also names `Crash13`, `China15`, `Timpani1..3`, `Triangle`, `BongoH`, `BongoL`, `Xylophone`, `Marimba`, `Glockenspiel`, `Gong`, `Tambourine1`, `Tambourine2` (class name = `BP_<name>_C`).

`DrumEvent` (all four required, no extra properties): `name` (instrument identifier hit; the converter writes the class name, e.g. `BP_Snare_C`), `vel` (integer 0-127), `loc` (integer hit location on the instrument; the converter always writes 0), `time` (**string** with seconds, e.g. `"12.3456"`, `%.4f`).

`BPMEvent` (required `bpm`, `time`): `bpm` number, `time` number seconds.

`audioFileData` (additionalProperties false; `calibrationOffset` required): `songTracks[]`, `drumTracks[]`, `songPreview`, `calibrationOffset` (integer ms).

`recordingMetadata` (required `artist`, `coverImagePath`, `creator`, `description`, `title`): `title`, `description`, `coverImagePath`, `artist`, `author`, `creator`, `length` (seconds, number), `complexity` (integer, 1-5 in the Song Creator; "typically 0-5").

## Timing model
- Event times are absolute seconds from the start of the audio (no beats, ticks or measures). MIDI is converted with the tempo map: for each tempo segment `time = segment_start_seconds + tick2second(ticks - segment_start_ticks, ticks_per_beat, tempo)`.
- `bpmEvents` / BPM events only describe the tempo (for the note highway grid); they do not affect `time`.
- `calibrationOffset` shifts audio versus chart in milliseconds.
- `length` is the larger of the last event time and the first audio track duration.

## Notes
- A "note" is a `DrumEvent`: instrument + velocity + location + time. There are no holds, sustains or mines; cymbal/tom distinctions are different instrument classes.
- Chords are several events with equal `time`. Order in the file is chronological in the converter output.
- MIDI mapping (YAML): per difficulty (`easy`, `medium`, `hard`, `expert`), drum name -> list of MIDI note numbers/ranges, with optional `toggle_note` (a note that must be held to switch the meaning, used for Rock Band tom/cymbal markers). Prebuilt maps: `rhythm_game_mapping.yaml` (Rock Band style), `rhythm_game_mapping_gh.yaml` (Guitar Hero), `midi_mapping.yaml` (defaults), `pdtracks_mapping.yaml`.
- The `loc` integer addresses multiple hit zones of one instrument; only value 0 is generated by tools. [other values: unknown]

## Audio & images
`songTracks` (drumless backing tracks, up to 5), `drumTracks` (up to 4; with 2/3/4 tracks the order is kick / snare / cymbals / toms per the guide), `songPreview`, `coverImagePath`. Every audio format supported; ogg recommended; MP3 padding can desync.

## Versions & variants
Schema v0.7 current; version 0 and 0.5 drum layouts exist (handled by a TODO in the converter). Kit files contain only `instruments` (version 0.5/0.7). Recordings contain `events` from play.

## Quirks & pitfalls
- `time` in `DrumEvent` is a string while it is a number in `BPMEvent`.
- Instrument name versus class: kits use `BP_<X>_C_<n>` instance names; the converter writes class names in events.
- `bpmEvents` versus `events` BPM entries (see above).
- The schema sets `additionalProperties: false` on events, instruments and metadata objects: strict validators reject unknown extra properties.

## Example
Constructed from the converter source and schema (illustrative, hand-built):
```json
{
  "version": 0.7,
  "authoringTool": "ParadiddleUtilities MidiConverter",
  "recordingMetadata": {"title": "Example", "artist": "Nobody", "creator": "me", "description": "", "coverImagePath": "cover.png", "complexity": 1, "length": 4.0},
  "audioFileData": {"songTracks": ["song.ogg"], "drumTracks": [], "songPreview": "", "calibrationOffset": 0},
  "instruments": [{"name": "BP_Kick_C_1", "class": "BP_Kick_C", "location": [-69.76, 60.32, 34.29], "rotation": [-96.77, 2.27, 38.0], "scale": [1, 1, 1]}],
  "bpmEvents": [{"bpm": 120.0, "time": 0}],
  "events": [{"name": "BP_Kick_C", "vel": 100, "loc": 0, "time": "0.0000"}, {"name": "BP_Snare_C", "vel": 100, "loc": 0, "time": "0.5000"}]
}
```
The `instruments` entry reuses the first values of `BP_Kick_C_1` from the shipped `drum_sets/defaultset.rlrr`.

## ROX support
Not read by ROX. Mapping to columns would require choosing a column per instrument class (10-piece kit); no holds, so tap-only.
